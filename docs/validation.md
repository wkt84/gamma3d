# ガンマ計算の照合

Gamma3D のガンマ計算が正しいことを、次の 3 つの方法で確かめています。

1. **解析解**: 答えが式で求まる合成データで、期待値と比べる。
2. **真値**: 総当たりの探索で求めた「真のガンマ」と比べる。
3. **pymedphys**: 広く使われている実装 [pymedphys](https://docs.pymedphys.com/) (`pymedphys.gamma`) と比べる。

結果の一覧は [validation/results.md](../validation/results.md) にあります。`npm run validate` を実行すると再生成されます。

> 照合の結果に関わらず、本ソフトウェアは **NOT FOR CLINICAL USE** です。

## 実行方法

```sh
npm run validate
```

1. `npm run gen:samples` でサンプルの RTDOSE を作る。
2. `node validation/export.ts` で照合用のケースを作り、Gamma3D で計算する。線量の配列と結果は `validation/.work/` に書き出す。
3. `uv run validation/compare.py` で、同じ線量の配列を pymedphys に渡して計算する。解析解・真値とも比べ、`validation/results.md` と `validation/results.json` を更新する。

Python 側の依存 (pymedphys 0.41.0、numba など) はスクリプトの先頭に書いてあり、uv が自動で用意します。すべて実行すると 10〜15 分かかります。`uv run validation/compare.py linear-shift` のようにケース名を渡すと、そのケースだけを確認できます (この場合、結果ファイルは更新しません)。

DICOM の読み込み処理の違いが結果に混ざらないよう、pymedphys には DICOM ではなく、Gamma3D が読み込んだ後の線量の配列 (float32) と格子の座標をそのまま渡しています。

## ケースと条件

| ケース | 内容 | 解析解 |
|---|---|---|
| linear-shift | 5%/mm の線形勾配を x 方向に 2 mm 平行移動 (1 mm 格子) | あり |
| uniform-offset | 一様な 2 Gy に +2% の線量差 (1 mm 格子) | あり |
| field-shift | 半影 (σ = 3 mm) のある直方体状の照射野を (1.5, −1, 0.5) mm ずらし、+1.5% の線量差 (2 mm 格子) | なし |
| sample | `npm run gen:samples` のサンプル。比較元は 2.5 mm 格子、比較先は 3 mm 格子の BEAM 2 本の合算で、ずれ・ノイズ・ホットスポットを含む | なし |

各ケースで、3%/3mm・3%/2mm・2%/2mm・1%/1mm のそれぞれを Global と Local で計算します (計 32 条件)。共通の設定は、γ 閾値 10%、基準線量は比較元の最大線量、γ 上限 2、探索分割数 10 です。pymedphys にも同じ値を渡しています (`lower_percent_dose_cutoff`、`global_normalisation`、`max_gamma`、`interp_fraction`)。

### 解析解

- **linear-shift**: 勾配 g の線形な線量を s だけ平行移動すると、γ = g·s / √(ΔD² + g²·Δd²) になる。Local では、ΔD を各点の比較元の線量から求める。
- **uniform-offset**: γ = |線量差| / ΔD。

比較するのは、探索球 (半径 = γ 上限 × DTA) と平行移動の分が比較先の格子に収まる内部の点だけです。

### 真値

各条件で、両者の差が大きいボクセル 20 点と、無作為に選んだボクセル 20 点について、真のガンマを求めます。

- 比較先は、両実装と同じく三線形補間で扱う。
- 2 つの実装の値は、どちらも実際に存在する探索点での値なので、真値の上界になる。そこで、小さいほうの値 × DTA を半径とする球の中を DTA/40 刻みで総当たりし、最良点から Nelder–Mead 法で詰めた値を真値とする。

## 合否の基準

- Gamma3D は、全条件で、真値との差 (と、解析解があるケースでは解析解との差) が **0.01 以内**であること。
- pymedphys とのパス率の差は参考値として記録します。目安は 0.5 ポイント以内とし、これを超えた条件については、真値との比較でどちらが正しいかを報告します。

pymedphys 自身にも、後で述べる探索の刻みによる誤差があります。そのため、pymedphys との一致そのものは基準にしていません。

## 結果の要点

詳しい数値は [validation/results.md](../validation/results.md) を参照してください。

- **解析解のあるケース**: パス率は pymedphys と完全に一致し、Gamma3D の解析解との差は 0.01 以内でした。
- **field-shift と sample**: 一部の条件で、pymedphys とのパス率の差が 0.5 ポイントを超えました。field-shift の 1%/1mm では約 5 ポイントあります。真値と比べると、Gamma3D の差は 0.01 以内で、pymedphys は最大 0.3〜0.45 高めの値でした。差の原因は pymedphys 側の探索の粗さです。
- **sample のパス率の差について**: それぞれの評価点で求めたパス率は最大で約 1.3 ポイント違います。これは評価する点の範囲の違いによるものです。比較元のうち比較先の格子の範囲外にある点を、Gamma3D は評価から除き、pymedphys は評価に含めてほぼ不合格にします。両方で評価した共通の点では、差は 0.01 ポイント程度です (1%/1mm を除く)。

## 照合で見つかり、修正した問題

この照合によって、Gamma3D 側の次の問題が見つかり、修正しました (E1、`chore/e1-validation`)。

1. **急勾配での谷の見逃し**
   - 探索の刻み (DTA/10) の間に線量が ΔD 以上変わる場所では、γ が小さくなる等線量面付近の谷が刻みより細くなります。格子点だけの探索では、その谷を見逃していました。Local や 1%/1mm で起きやすく、最悪の例では真値 0.45 に対して 1.59 を返していました。
   - 修正: 隣り合う格子点の間で、比較先と比較元の線量の大小が入れ替わる辺については、等線量面との交点 (線形補間) も探索点に加えました。
   - このような急勾配を検出した点だけ、探索の打ち切りに 1 刻みの余裕を持たせています。
2. **比較先の格子の端**
   - 最小値が比較先の格子の外に来る点では、真の最小値は格子の境界上にあります。3 段の局所的な詰めでは、境界に十分近づけていませんでした (誤差は約 0.024)。
   - 修正: 詰めの途中で格子の外に当たった場合は、刻みの 1/128 まで詰めるようにしました。
3. **γ 上限の直前の値**
   - 探索半径ちょうどの格子点を評価する前に打ち切っていました。また、格子上の最良値が上限をわずかに超えると、局所的な詰めを行っていませんでした。その結果、真値が 1.975 のような点を、上限 (2) として返していました。
   - 修正: 探索半径ちょうどの点まで評価し、上限より 1 刻み以内の値も詰める対象にしました。

pymedphys (0.41.0) にも、1 と 3 に当たる誤差が見られます。pymedphys は同心の球殻の上を探索し、刻みを距離に応じて広げる (`distance / interp_fraction / max_gamma`) ため、急勾配では真値より高めの値になります。

## 既知の制限

- 真値は、有限の刻みと局所最適化で求めた近似値です。差の大きいボクセルと無作為のボクセルだけを調べているので、全ボクセルで保証するものではありません。
- 対象は合成データとサンプルだけです。各社の治療計画装置 (TPS) が出力した実データでの確認は、v3 以降の候補 (E3) です。
- 照合は CI には入れていません (実行に 10 分以上かかるため)。計算コアを変更したときは、手元で `npm run validate` を実行し、`validation/results.md` の差分を PR で確認します。
